Đang chờ traffic…

Hệ thống mô phỏng 4 thuật toán trên chính các request thật vừa đi qua Load Balancer của lượt gửi gần nhất (cập nhật mỗi 2 giây) và đề xuất thuật toán phù hợp nhất.

4 thuật toán cùng lúc

Mỗi request đi qua Load Balancer được đưa vào cả 4 sơ đồ. Sơ đồ đang chạy là số liệu thật của Load Balancer, 3 sơ đồ còn lại là mô phỏng trực tiếp trên cùng luồng request.

  • Viền đậm, nhãn ĐANG CHẠY: thuật toán Load Balancer đang dùng
  • Viền xanh phát sáng, nhãn TỐI ƯU NHẤT: thuật toán nên chọn

Lịch sử chuyển thuật toán

Mỗi sơ đồ là 1 giai đoạn: Load Balancer đã chia request cho các server thế nào khi chạy thuật toán đó (số liệu thật). Đổi thuật toán sẽ thêm 1 sơ đồ mới bên cạnh để so sánh cách chia trước và sau khi đổi.

Chưa có request nào. Bấm Bắt đầu gửi, rồi đổi thuật toán trong lúc gửi để so sánh.

  • Đường càng dày = Load Balancer chia càng nhiều request cho server đó (% ghi trên đường)
  • 12Số request server nhận trong giai đoạn
  • Hàng đợi lớn nhất
  • Quá tải từ 1 giây trở lên trong giai đoạn

Request được tính cho thuật toán đã chọn server cho nó. Vài giây đầu sau khi đổi, các server vẫn còn hàng đợi do thuật toán trước để lại.

So sánh 4 thuật toán

Mô phỏng 4 thuật toán trên đúng các request thật của lượt gửi gần nhất, xếp theo thời gian chờ trung bình. Mỗi lần bấm Bắt đầu gửi, bảng này và 4 sơ đồ bắt đầu lại từ đầu; gửi xong kết quả vẫn được giữ lại.

Chưa đủ dữ liệu để so sánh (cần ít nhất 20 request). Bấm Bắt đầu gửi ở trên.

Web Server

Chỉnh ngay khi đang chạy: đổi hệ số chậm, bật / tắt từng server. Thêm / bớt server khi không gửi request. Cả 4 sơ đồ và phần đề xuất cập nhật theo cụm server mới.
